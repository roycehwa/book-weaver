# Phase A 流程级质量重构

状态：本文件只定义当前新流程。流程开发已完成并通过合成自动验收；真实书新建任务验收尚未开始。

截至 2026-09-19 已完成：

- 新增格式中立的 `bookweaver_reading_units_v1` 契约、指纹、守恒校验和 `reading-units.json` 产物；intake 预览为 `translation_authority: false`，用户确认后冻结为 `true`。
- PDF 保存 Docling 节点/字符 span；同一节点跨页时确定性恢复源分隔符和有证据的页末断词，并将多页 span 投影到 reading unit。EPUB 保存资源路径、DOM 路径、元素字符范围、元素 ID 和链接目标。用户在章节确认区可查看当前选中章节的重建连续正文，并与原文件预览对照。
- intake 后先进入 `awaiting_chapter_confirmation`，不再提前提取术语；用户确认后从 canonical book 的可翻译范围生成术语候选，再进入 `awaiting_glossary`。
- 用户确认后的 `auto` 会固化为明确动作；正文默认 translate，Notes/Bibliography/Glossary 建议 preserve，Index 建议 exclude。确认后重写 reading units，使预览与确认版结构、策略同步。
- 章节范围变化时保留仍出现在新翻译范围内的已定稿术语，移除已离开范围的 active 项，并要求重新定稿。
- chapter segments 与实际运输分块从确认版 reading units 生成；每段带 reading-units 指纹和 unit IDs，超长单元的 transport parts 共享同一个 unit ID，调整分块大小不再创建新的逻辑段落。
- PDF 高把握跨节点续接与 EPUB 跨 XHTML 资源续接已经使用格式各自的正向/阻断证据，并共用续接决策台账、稳定指纹和独立 provenance。
- Notes/Endnotes 略过提示已经依据真实内部链接工作；用户可按建议保留原文，也可明确确认略过，确认记录受当前依赖编号约束。
- 源文、原始译文与润色结果的质量门已经分离；确定性中文清洁先于受约束润色，签名和 currentness 检查阻止过期结果进入审阅或导出。
- 章节旧窗口冲突、导出跨进程锁、后端重启恢复、重复提交、EPUB/PDF 原子发布和失败重试已有合成自动验收。

尚未完成：用新建任务完成真实书端到端验收并统计每百页人工修正数。真实书只作为通用流程的验收样品，不在产物上做局部补丁。

## 1. 当前流程为何会放大问题

当前 PDF 路径大致为：Docling 结构化文本 → 按 provenance 拆到各页 → 页内几何合并 → 按页生成 Markdown → 用户确认章节 → 以双换行拼接页面 → 按 Markdown 块分块 → 翻译。

这里有一条系统性失真链：

1. Docling 的一个文本节点可能已有多个页面 provenance 和字符范围，说明它本来是同一个逻辑段落。
2. `_extract_text_blocks` 为了页码归属将其拆成片段，但没有在后续阅读结构中保留共同节点身份。
3. `_join_geometric_continuations` 只合并同页片段，明确不处理跨页续接。
4. `apply_canonical_chapter_plan` 使用双换行拼接逐页 Markdown。
5. `split_markdown_into_chunks` 将双换行解释为真实 Markdown 块边界，并要求翻译维持该结构。

因此，分块器本身没有制造错误，而是忠实保存了上游制造的假段落。仅在分块时重新排布只能缓解表象，还会丢失原始页面和坐标证据。

EPUB 虽然没有固定页面和 PDF 几何断行问题，也不能绕过重建与确认。EPUB 的 XHTML 文件边界、`spine` 项、HTML 段落、样式 span 和导航条目并不天然等于用户希望看到的逻辑章节与翻译单元；不规范 EPUB 还可能包含碎片化文本节点、重复标题、导航与正文不一致、脚注关系丢失或一个逻辑章节跨多个资源。两种格式需要不同的输入适配器，但必须归一到同一种逻辑文档模型。

## 2. 建议调整后的主流程

原流程中的“术语先于原文/章节确认”也应调整。建议采用：

1. **格式解析层**：PDF 保存 Docling 原始节点、字符、节点身份及全部页面 provenance；EPUB 保存 package、spine、navigation、XHTML DOM、资源与链接关系。任何一种解析结果都不直接作为翻译输入。
2. **统一逻辑阅读单元层**：PDF 在保留多页 provenance 的前提下恢复结构；EPUB 根据 DOM 语义、spine 阅读顺序和链接关系归一结构。两者输出同一种段落、标题、列表、引文、图片和注释单元。
3. **翻译前源文清洁与质量门**：处理页界噪声、明确断词、控制字符等；记录每项变换。高风险问题进入原文确认台。
4. **用户确认重建后的原文、章节和内容策略**：PDF 用户看到的不是逐页拼接文本，EPUB 用户看到的也不是原始 XHTML 文件清单；两者看到的都是实际将进入翻译的连续逻辑文档。
5. **从确认后的可翻译范围提取术语**：不再让被排除的 Index、Notes 或脏断词污染术语候选。
6. **用户定稿术语**。
7. **冻结确认输入**：冻结阅读单元版本、章节策略和术语版本。
8. **传输分块与翻译**：分块只解决模型长度限制，不决定段落结构。
9. **翻译完整性与术语质量门**：检查单元覆盖、实体、编号、术语、漏译和结构，不合格片段有界重译。
10. **确定性目标语言清洁**：统一中文标点、引号、中文与拉丁字符间距；输出差异记录。
11. **受约束润色与异常审阅**：只改善中文表达，不能改变术语、引用、单元覆盖或用户修订。
12. **排版、导出与真实阅读验证**。

## 3. 逻辑阅读单元：PDF 与 EPUB 的统一中间层

新增稳定的中间层，例如 `reading-units.json`。每个单元包含：

- 稳定 `unit_id` 和类型：paragraph / heading / list_item / quote / figure / note；
- 完整逻辑文本；
- 一个或多个 provenance span：PDF 使用页码、坐标和字符范围；EPUB 使用资源路径、DOM 路径、元素/字符范围和链接锚点；
- 与前后单元的边界类型：paragraph / continuation / uncertain；
- 自动修复记录、置信度和人工决定；
- 源文版本及内容指纹。

合并规则分两级：

1. **确定性恢复**：同一 Docling 节点的多页 provenance 重新组成一个阅读单元。页码归属通过 span 保存，不再通过拆段实现。
2. **高把握跨节点续接**：前段靠近页底、后段靠近下一页页首、同栏和相近字体、前段不是完整句、后段为小写续写；英文行末连字符按词级规则处理。只有证据同时成立才自动合并。

中等把握候选进入原文确认台。段落单元可以跨页，但不能跨章节、标题、列表、引文、注释或图片边界。

EPUB 使用与 PDF 不同的重建证据：

1. 按 package spine 建立唯一阅读顺序，以 navigation/landmarks 作为章节候选而非绝对真相。
2. 将同一语义块内被内联标签或样式 span 切碎的文本恢复为一个阅读单元，同时保留 DOM provenance。
3. 识别跨 XHTML 资源延续的逻辑章节，但不因文件边界自动制造新章节或新段落。
4. 保留脚注、尾注、图片、标题和内部链接关系；发现悬空锚点、重复内容或导航冲突时进入确认台。

因此，“重建”不是 PDF 专属的版面修复，而是所有输入格式进入翻译前都要完成的逻辑文档归一化。格式适配器负责提取证据，后续确认、术语、分块、翻译、润色和导出共同消费统一阅读单元。

## 4. 源文清洁和中文标点必须分开

### 翻译前可以做

- 清除位于页界窗口中的页码、运行页眉及已知乱码序列；
- 去除控制字符、软连字符和明确的 PDF 行末断词；
- 修复明确的词内拆分，前提是有几何或原始 PDF 文本层证据；
- 规范源语言中由提取造成的标点空格，例如 `word ,`；
- 将所有变更写入可撤销的 source-edit log。

段尾 `-`、`---`、`-x -` 等不能用全书正则无条件删除。应只在 provenance 页界附近、且与原始 PDF 文本层或页眉页码证据冲突时清除。这样同一机制可以同时解决段尾乱码、跨页断句和词内断开。

### 翻译前不应做

- 不把英文逗号、引号、冒号提前替换成中文标点；
- 不修改引文、书名、代码、公式、URL 或外文术语的原始标点；
- 不用中文排版规则污染源文和源文指纹。

中文全角标点属于译文规范，应在翻译后、润色前由确定性规则处理，并跳过代码、URL、拉丁引文、公式和受保护术语。翻译质量检查同时要求模型优先输出目标语言标点，确定性清洁负责收尾。

## 5. 分块器的新职责

分块器接收已确认的阅读单元，而不是逐页 Markdown：

- 默认只在阅读单元之间切块；
- 超长段落按句子运输拆分，但所有 part 共享同一 `unit_id`，保存字符范围和 `separator_before`；
- 重新组装必须通过字符覆盖、顺序和 round-trip 指纹检查；
- 分块大小变化不得改变段落、页码归属、章节或审阅单元；
- 翻译失败和局部重译以阅读单元为用户可见范围，以 transport part 为模型请求范围。

这样调整 `max_chunk_chars` 或模型上下文不会改变成书结构。

## 6. 简化模式与 Notes 的策略

当前简化模式将所有候选统一改为 `exclude`，等价于“不翻译、不导出”。应改为“附录处理建议”，按依赖关系给出不同默认值：

| 类型 | 建议策略 | 理由 |
| --- | --- | --- |
| Notes / Endnotes | **保留原文，不翻译** | 正文注号依赖它，删除会使学术引用断裂 |
| Bibliography / References | **保留原文，不翻译** | 书目信息通常无需翻译，且正文可能引用 |
| Glossary | 保留原文；提示用户可改为翻译 | 是否需要翻译取决于阅读用途 |
| Index | 默认建议略过 | 纸书页码对可重排 EPUB 通常失效；仍允许保留 |
| Author biography / Credits | 建议略过或保留，由用户选择 | 通常没有正文依赖 |

界面应显示每章将采取的明确动作，不再由一个复选框静默删除全部候选。如果 Notes 存在正文引用，用户选择“略过”时应出现依赖提示；最终确认仍属于用户，不由系统代签。

`auto` 也应改变语义：自动分类只生成“建议”，用户确认后的动作必须写成明确的 translate / preserve / exclude。后续重建不得再以章节标题规则覆盖用户确认结果。这同时解决 `Acknowledgements` 标为正常处理却被隐藏改成保留英文的问题。

## 7. 各阶段质量门

### 源文质量门

- 每个原始字符必须有唯一去向：保留、明确清洁、用户排除；
- 跨页阅读单元可追溯到全部源页；
- 页界乱码、控制字符、可疑断词和未决续段有明确计数；
- 高风险未决项阻断翻译，低风险项进入用户确认。

### 翻译质量门

- 每个可翻译 `unit_id` 都有译文或明确失败状态；
- 数字、引用标记、专名、受保护术语和 Markdown 结构守恒；
- 未译英文从“固定词表扫描”升级为源译对齐检查；
- 模型不能通过返回原文或改变段落数冒充成功。

### 润色质量门

- 只能修改已有译文文本；不能创建、删除或合并阅读单元；
- 保护术语、外文括注、`life/Life` 之类的大小写语义差异、引用编号和人工编辑；
- 每项修改有前后差异，高风险修改回到异常审阅。

### 导出质量门

- Notes 引用依赖完整；保留或排除决定进入交付清单；
- 导航、标题、图片、元数据及内部链接验证通过；
- 窄屏和宽屏阅读验证属于导出验收，不用于掩盖上游内容缺陷。

## 9. 验收样例

- 一个英文单词在页末以连字符断开，下一页续写：翻译输入中恢复为一个词，provenance 同时指向两页。
- 一个段落自然跨页：翻译输入保持一个段落；调整分块大小后段落结构不变。
- 下一页确实开始新段：不能因小写或标点启发式被错误合并。
- 页眉、页码被 Docling 混入正文节点：只删除页界污染字符，并保留变更证据。
- Notes 设为保留原文：不调用翻译，仍出现在 EPUB，正文注号可以到达注释。
- Notes 设为略过：界面明确提示正文存在依赖，用户确认后记录决定。
- 中英文混排译文：中文标点规范化不改变 URL、公式、外文引文和 `life/Life`。
- 一个结构良好的 EPUB：重建预览保持原有阅读顺序、章节、段落、图片及注释链接，用户确认后再提取术语。
- 一个结构不规范的 EPUB：XHTML 文件边界、内联 span 和导航冲突不能直接变成假章节或碎片化翻译单元；异常须可追溯到原始 DOM。

缺少当前规范工件的运行目录直接拒绝继续处理；所有能力必须使用新建任务和新中间层验收。
