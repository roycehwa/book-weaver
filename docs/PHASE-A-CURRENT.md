# Phase A：唯一续接摘要

更新：2026-09-19。用途：新开发对话的唯一规范入口。本文件只记录当前新流程、当前验证和待完成事项。

## 1. 目标与边界

将 BookWeaver 做成个人使用、可人工干预、可恢复、能可靠导出的书籍翻译应用。首发支持 EPUB 和文字型 PDF；扫描件及复杂多栏超出首发质量承诺。

- 只做 Phase A：解析、术语、章节、翻译、审阅、导出。不做知识拆分、多用户或完整排版编辑器。
- 先通过本机真实书籍质量与故障恢复验收，再考虑腾讯云。目标不是修好某一本书，而是修好通用算法。
- 原则上每百页必须手工修正的问题不超过 5 处；同类问题反复出现必须修算法。警告数量不等于人工修正数量。
- 零星内容判断允许人工干预；网络暂态故障与常规恢复不应反复把流程推给用户。不得无限重试、吞错或用原文冒充成功译文。

## 2. 不可绕过的工作流

格式解析 → 逻辑文档重建 → 用户确认重建后的原文、章节和内容策略 → 从确认范围提取并定稿术语 → 冻结输入 → 传输分块 → 翻译 → 异常审阅 → 导出。

- 术语、章节由用户确认，助手不能自动代签。术语数量由内容质量决定，不追求固定配额。
- 后端统一执行版本及启动检查；运行时冻结输入。上游修改使受影响结果过期，保护人工修订与批准版本。
- 原文件不变；原文修正可撤销。重复提交幂等，旧页面保存不能覆盖新版本。
- 可局部重译，重译要求允许为空；无关章节尽量复用，人工批准内容不被重试覆盖。
- 必须阻断：归属缺失、任务未完成、必需图片缺失、过期译文、生成失败。
- 疑似断词、术语差异、可能未译等可修正或注明理由接受。“保留原文/略过”是明确记录的用户决定，不计为翻译成功。
- 导出先临时生成并验证，再发布；失败不覆盖旧成品。图片不静默删减或降清晰度，异常体积要可解释。

## 3. 当前新基线

只有当前新流程代码、当前自动化测试以及由当前流程创建的完整验收任务可以证明能力。

- PDF 与 EPUB 都必须先归一为统一的逻辑阅读单元，再向用户展示实际待翻译文档并确认。PDF 依据节点、页码和几何 provenance 修复跨页结构；EPUB 依据 package、spine、navigation、XHTML DOM 和链接关系归一结构。EPUB 不套 PDF 断行规则，但也不把原始 XHTML 文件边界直接当成章节或翻译单元。
- 封面使用明确资源，不把出版社标志或第一张普通图片充当封面。
- 可解析目录/表格优先文字；空表格内嵌文字节点也要读取，不能直接转图。
- 简化模式默认关闭；识别后部 Notes、Bibliography、Glossary、Index 等候选，由用户确认正常处理、保留原文或略过。没有自动候选也允许手动指定。
- 章节插入使用明确标题与页范围，更新相邻范围；左栏保留页码输入，不显示内部文件链接。
- 用户已确认正文的翻译策略优先于自动页面分类，避免正文误判成参考文献后整章跳过。
- 同页下一章标题唯一匹配时按标题位置拆分，保留页内范围并检查遗漏/重叠；不确定时不猜。排除后章也不能丢弃同页前章结尾。
- 导出检查整章被错误跳过翻译的情况。这不是完整语义质量证明。
- 全文重新排版仍是独立设计项，见 REFLOW-DESIGN-2026-09-18.md，不能当成已实现功能。

- Phase A 页面终点为审阅、导出与完成。
- 用户界面保持四个阶段：导入；查看重建结果并确认；确认术语；审阅与导出。PDF 与 EPUB 的格式适配、质量检查和恢复状态均留在后台，不增加用户执行次数。
- 一本文字型 PDF、一本结构良好 EPUB 的最新完整验收及每百页人工修正统计尚未统一闭环；云端验收未完成。
