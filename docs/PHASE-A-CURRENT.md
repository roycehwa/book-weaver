# Phase A：唯一续接摘要

更新：2026-09-22。用途：新开发对话的唯一规范入口。本文件只记录当前新流程、当前验证和待完成事项。

## 1. 目标与边界

将 BookWeaver 做成个人使用、可人工干预、可恢复、能可靠导出的书籍翻译应用。首发支持 EPUB 和文字型 PDF；扫描件及复杂多栏超出首发质量承诺。

- 只做 Phase A：解析、术语、章节、翻译、审阅、导出。不做知识拆分、多用户或完整排版编辑器。
- 先通过本机真实书籍质量与故障恢复验收，再考虑腾讯云。目标不是修好某一本书，而是修好通用算法。
- 原则上每百页必须手工修正的问题不超过 5 处；同类问题反复出现必须修算法。警告数量不等于人工修正数量。
- 零星内容判断允许人工干预；网络暂态故障与常规恢复不应反复把流程推给用户。不得无限重试、吞错或用原文冒充成功译文。

## 2. 不可绕过的工作流

格式解析 → 逻辑文档重建 → 用户确认重建后的原文、章节和内容策略 → 从确认范围提取并定稿术语 → 冻结输入 → 传输分块 → 翻译 → 异常审阅 → 导出。

- 术语、章节由用户确认，助手不能自动代签。术语数量由内容质量决定，不追求固定配额。
- 后端统一执行版本及启动检查；运行时冻结输入。上游修改使受影响结果过期，保护人工修订与批准版本。
- 原文件不变；原文修正可撤销。重复提交幂等，旧页面保存不能覆盖新版本。
- 可局部重译，重译要求允许为空；无关章节尽量复用，人工批准内容不被重试覆盖。
- 必须阻断：归属缺失、任务未完成、必需图片缺失、过期译文、生成失败。
- 疑似断词、术语差异、可能未译等可修正或注明理由接受。“保留原文/略过”是明确记录的用户决定，不计为翻译成功。
- 导出先临时生成并验证，再发布；失败不覆盖旧成品。图片不静默删减或降清晰度，异常体积要可解释。

## 3. 当前新基线

只有当前新流程代码、当前自动化测试以及由当前流程创建的完整验收任务可以证明能力。

- PDF 与 EPUB 都必须先归一为统一的逻辑阅读单元，再向用户展示实际待翻译文档并确认。PDF 依据节点、页码和几何 provenance 修复跨页结构；EPUB 依据 package、spine、navigation、XHTML DOM 和链接关系归一结构。EPUB 不套 PDF 断行规则，但也不把原始 XHTML 文件边界直接当成章节或翻译单元。
- 封面使用明确资源，不把出版社标志或第一张普通图片充当封面。
- 可解析目录/表格优先文字；空表格内嵌文字节点也要读取，不能直接转图。
- 简化模式默认关闭；识别后部 Notes、Bibliography、Glossary、Index 等候选，由用户确认正常处理、保留原文或略过。没有自动候选也允许手动指定。
- 章节插入使用明确标题与页范围，更新相邻范围；左栏保留页码输入，不显示内部文件链接。
- 用户已确认正文的翻译策略优先于自动页面分类，避免正文误判成参考文献后整章跳过。
- 同页下一章标题唯一匹配时按标题位置拆分，保留页内范围并检查遗漏/重叠；不确定时不猜。排除后章也不能丢弃同页前章结尾。
- 导出检查整章被错误跳过翻译的情况。这不是完整语义质量证明。
- 可选的“阅读版”全文重排仍是独立后续功能，见 REFLOW-DESIGN-2026-09-18.md；它不属于本轮既定流程开发，也不能当成已实现能力。

- 章节更新期间界面明确显示正在重建确认版书籍、权威阅读单元、运输分块及术语候选；成功后刷新术语并滚动到术语定稿，源文质量未通过时则留在章节确认区并显示原因，不再呈现无状态的“卡死”。
- 源文质量门已前移到章节确认与术语提取之间。PDF 碎片清理不枚举特定字母或少量英文词；任意相邻碎片必须同时获得整书完整词形、通用英语词频和碎片形态证据才会自动合并，横线杂质按独立行、句末段落边界或并列句法位置识别。数学正文中的 `-x-` 和缺乏把握的行末连字符保持不变并进入质量审计。阻断项不生成术语、不启用翻译，也不调用供应商或自动重试。
- 术语频次只用于通过术语资格门后的排序，不能再把普通单词变成术语。单词候选须有定义、真实索引或“引号加低通用词频”证据；从句引导词、代词尾、连接片段、姓氏缩写及人物并列会被结构门排除。候选记录提取证据类型，概念标题不再误标成人名。
- 术语重提取和专业类型切换统一从用户确认后的 canonical book 读取，严格遵守章节 translate/preserve/exclude 策略；不得退回未确认 `book.json`，因此 Notes、Bibliography、Index 不会在用户选择保留或略过后重新污染候选。
- 原文修正台不再把“段落以连字符结尾”这一弱文本启发式扩张成数百个用户待办；跨页续接只由结构化 continuation ledger 判断，不确定边界在确认质量区集中呈现。真实任务复算后原文修正台的 227 个版面待核对项归零。
- Docling 句中段尾的包裹式单字形流标记（例如 `-x-` 后接空行和小写续文）会在确认版重建时自动移除，并将被打断的句子重新接为一个连续段落；内联数学 `-x-` 和未获充分证据的真实连字符保留。罕见但有词频证据的单字形拆分（例如 `c oncatenation`）也在翻译前自动合并。真实任务复算得到 source quality `passed`、0 finding，未调用翻译模型。
- 成功重建确认版会清除旧的 `failed_stage` 和错误信息，避免修复后界面仍显示失败。术语排除是持久用户决定，章节重建、术语重提取和专业类型切换不得清空 `excluded_sources`。
- 模型偶发回显完整 `<SOURCE_MARKDOWN>...</SOURCE_MARKDOWN>` 运输包装时，翻译入口只在该包装覆盖整个回复时自动剝离，不影响正文内联 HTML。脚注标记或语义 HTML 标签被模型改动时，现在会在单个翻译片段写入缓存前失败并有界重试，不再到全书审阅完成后才形成无法定位的导出死路。
- PDF 断行词不再由脱离页面与版面证据的正则表达式一律当作全书阻断。系统先用词形频率和整书词形证据自动区分并修复版面断词与真实连字复合词；无法证明的残留只作为重建质量提示，不再在章节确认后冻结整书。解析阶段的质量报告现在会在首次章节确认前显示；替换字符、控制字符、阅读单元失效等确定性损坏仍继续阻断。
- 解析阶段发现的源文问题在首次章节确认前即带有源文件定位。PDF 使用实际页码和页内段落编号，EPUB 使用阅读页和段落编号；重复出现的同类损坏按阅读顺序分别定位，无法唯一匹配时不猜位置。确认区的定位按钮会直接打开相应页并选中具体段落，不再用全书 Markdown 行号要求用户自行寻找。
- PDF 不再把不同 Docling 节点天然视为不同段落。未结束的页末句子在下一页以小写续文时继续使用原有高把握续接；下一页以专名或引语的大写字母开始时，只要页底/页首、同栏、无新段缩进、样式一致且不存在标题、列表、表格或图片障碍，也会自动续接。已经完整结束的句子不会仅凭同栏自动合并，避免吞掉无首行缩进书籍中的真实新段。
- 审阅编辑的自动保存、显式保存、最终确认和返回控制台共用串行版本号，不会再由同时发出的旧版本请求互相覆盖或拒绝。界面提供“保存当前修改”和失败重试，切换范围、章节标记、重新校验、导出及返回前都会等待项目文件写入；未同步内容离开页面时会触发保护提示。尚未确认的手工草稿不能绕过确认直接导出，批准后的人工译文由导出装配读取并替换对应段落。
- 原始译文质量门不再用整书顶层段落数量是否完全相等来判断 Markdown 结构损坏。标题层级、列表及列表项、引文、代码、表格、分隔线、图片、链接和 HTML 等受保护结构变化继续阻断；只有正文段落边界在完整交付装配后变化时降为审阅提示。分块翻译入口仍逐块要求精确结构并执行失败重试，质量规则版本已升级，旧任务须显式重新校验才能采用新判定。

2026-09-22 新任务验收反馈与通用修正：

- 跨页边界记录与章节内容策略在界面上分开。已接受的边界已合并为一个逻辑段落；结构证据拒绝续接的边界作为无需操作的审计记录；证据不足的可翻译范围保留为两个段落并提示核对。跳转相关页时默认选中页末段落；原文修正台的“内容去留”明确说明不控制跨页续接。尚未为不确定跨页边界增加用户手动合并操作。
- 翻译供应商以明确的 `input/output new_sensitive (1026/1027)` 或 `content_filter` 拒绝零星正文片段时，停止对同一内容的整轮自动重复请求。仅此类被记录为供应商内容拒绝的正文片段可由用户选择“留到审阅时补译”；“明确保留原文”也只对明确内容拒绝开放，且须填写理由。两类例外共用上限：全书翻译块数的 1%，最少 1 个、最多 5 个。超时、网络、结构及其他翻译失败不适用，只能恢复重试或填写人工译文。所有失败片段处理完毕后，系统自动从检查点续行；用户主动暂停的任务不自动恢复。待补译原文在审阅中保持开放，补入中文并批准前持续阻断导出；含此类占位的整书跳过模型润色，避免再次提交该片段。脚注仍须在失败清单处理。当前真实任务的 1 个已选例外经检查点恢复进入审阅，111 个已完成块保留；这一实际任务不替代新建任务验收。

故障恢复自动验收矩阵：

| 场景 | 当前自动证据 |
| --- | --- |
| 断网、超时、模型暂态失败 | 有界重试、失败分类、暂停/恢复与缓存保留测试 |
| 后端重启 | 翻译/导出子进程继承文件锁；停滞翻译与导出由监督器接管 |
| 重复提交 | 重复上传显式确认；重复导出返回当前任务且不派发第二 worker |
| 旧窗口保存 | 原文、章节与审阅分别使用 revision 冲突检查，旧内容不能覆盖新内容 |
| 边界变化 | continuation/reading-unit 指纹变化使旧运输输入和下游产物失效 |
| 导出失败 | EPUB/PDF 临时生成；注入失败时旧成品保留，清除临时文件；失败后可重试完成 |
| 缓存续跑 | 未变化内容按内容指纹复用；暂停和网络恢复不删除有效缓存 |
| 人工修改 | 草稿、批准译文和未受影响决定在刷新、重试和局部变化后保留 |
